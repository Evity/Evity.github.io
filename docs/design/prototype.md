# 页面与交互原型

本文件是可用于开发交接的结构原型；视觉、尺寸和组件状态以根目录 DESIGN.md 为准。当前所有文章为演示内容。

## 1. 首页 `/`

首页结构（桌面）：

1. 导航：日常之间 / 首页 / 生活 / 代码 / 关于。
2. 简介：认真生活，慢慢记录。吃过的味道、喜欢的歌，还有路上的风景。
3. 精选：左侧 3:2 早午餐大图，右侧分类、标题、摘要、日期和阅读入口。
4. 最新记录：左侧两列图文预览，右侧带唱片场景图的「最近在听」、生活分类入口和关于这里简介。
5. 页脚：生活归档与示例素材说明。RSS 留待公开域名确定后补充。

| 图文预览 | 图片 | 示例标题 |
| --- | --- | --- |
| 吃的记录 | 3:2 餐桌照片 | 和朋友吃饭，值得慢一点 |
| 咖啡手记 | 3:2 咖啡照片 | 碰杯之前，先闻到咖啡香 |
| 音乐随记 | 完整封面或唱片场景照 | 让唱片陪一个安静的傍晚 |
| 旅行途中 | 3:2 山景照片 | 去山里，换一种呼吸 |

照片为 Unsplash 演示素材，文章并非作者真实经历。音乐场景照不等于实际专辑封面。素材来源见 [图片清单](assets/SOURCES.md)。

首页先限定为已发布的生活文章，再从中选择作者指定的一篇精选；最新记录只从剩余生活文章按发布日期倒序取最多 4 篇。代码文章无论日期或精选标记都不进入首页。全部文章入口进入 `/life/`；生活归档只包含生活内容，RSS 留待后续实现。没有精选时直接展示最新记录，无内容时展示欢迎说明。

## 2. 栏目页 `/life/` 与 `/code/`

生活页标题「生活，总有值得记下的事。」；副文案「吃过的味道、喜欢的音乐、咖啡、旅行与日常小事。」展示全部/吃的记录/咖啡/音乐/旅行/日常筛选，使用两列图文预览，手机单列，封面可选。

代码页标题「把学过的，慢慢弄明白。」；副文案「这里留给代码学习与实践。生活首页仍然只展示生活记录。」以标题、摘要与主题标签为主要信息，无需给每篇代码笔记配无关图片。提供全部、学习笔记、实践项目、问题复盘筛选。

类别路由示例：`/life/food/`、`/life/travel/`、`/code/learning/`、`/code/projects/`、`/code/retrospectives/`。保留语义 URL，不绑定某个托管平台的服务接口。

```text

一行栏目介绍
全部   吃的记录   咖啡   音乐   旅行   日常       ← 当前项清晰标记
───────────────────────────────────────────
分类 · 日期       标题、摘要          可选封面
分类 · 日期       标题、摘要          可选封面
分类 · 日期       标题、摘要          可选封面
───────────────────────────────────────────
```

仅当筛选结果超过 10 篇时显示分页；当前示例内容未达到该阈值。

## 3. 文章页 `/posts/<slug>/`

生活与代码使用同一个阅读模板，按内容启用封面、目录、代码块等能力。

```text
导航
生活 / 吃的记录 或 代码 / 学习笔记
文章标题
发布日期 · 可选更新时间
导语
可选封面 + 图注
┌──────────────────────────────┬─────────────┐
│ 正文：最大 720px             │ 本文目录    │
│ H2 章节                      │ 第一节      │
│ 段落 / 照片 / 引用           │ 第二节      │
│ 代码语言               复制  │ 第三节      │
│ 代码块可局部横向滚动         │             │
└──────────────────────────────┴─────────────┘
主题标签
相关文章（最多 2 篇，先限定同栏目，再按标签匹配，无匹配则省略）
返回栏目
页脚
```

## 5. 关于与归档

- `/about/`：作者介绍、博客主题、最近关注、真实联系链接。未提供姓名/头像/社交地址时使用明确的编辑占位，不编造履历。
- `/archive/`：默认仅含生活文章；代码归档从代码页进入。按年份分组，日期 + 标题 + 栏目，纯文字列表。当前示例少于 10 篇；超过 10 篇后每页最多 10 篇并提供分页。
- 404：说明文章未找到，提供首页与归档入口，不自动跳转。

## 6. 内容与部署边界

当前文章以 Astro 内容集合中的 Markdown 文件维护，随 Git 管理；Astro 7 与 Bun 1.3.14 已锁定。Cloudflare Workers 与 Vercel 均保留为后续部署候选，部署细节见 [部署方法论](../DEPLOYMENT.md)。

内容字段：标题、唯一 slug、摘要、发布日期、可选更新时间、栏目（生活类别或 code）、可选代码主题、标签、可选封面与有序 gallery（图片、替代文本、图注）、可选精选标记、草稿标记、正文。草稿不得进入公开列表或构建产物。图片来源记录在素材清单中；credit 和 focalPoint 字段可在作者内容需要时扩展。

听歌近况独立于文章维护，含描述、更新时间，可选曲名、艺人、专辑及真实平台链接。没有有效链接时作为静态文字；无自动播放或模拟播放器。

生活类别为 food / coffee / music / travel / daily。食物记录可附店名、菜名、到访日期与个人感受；咖啡可附店名或豆子、冲煮方式与风味笔记；音乐可附曲名、艺人、专辑与听歌感受；旅行可附目的地、旅行日期与图片图注。均为可选字段，短记录不必写成长文，也不强制评分。

代码页保持独立的文章列表，不在首页展示技术推荐或学习近况。生活文章的相关推荐仅在 life 内匹配，避免通过共享标签混入技术内容。

面向 Cloudflare Workers / Vercel 的设计约束：阅读与栏目导航不依赖登录或运行时数据库；图片可随站点发布或使用独立资源地址；文章 URL 稳定。平台适配、构建命令、域名、GitHub 仓库与自动发布流程在开发阶段核验和配置。本轮没有创建远程仓库或执行部署。


## 7. 图片阅读路径

首页图片与标题进入同一篇文章；首页不承担相册轮播。进入文章后，读者先看到封面与导语，再按正文顺序查看原比例图片：美食可展示菜品与环境，旅行可展示路线中的场景，音乐展示完整封面及听歌文字。每张照片可附图注；当前原型不提供点击查看原图或灯箱。

开发时将预览、正文和原图作为不同尺寸资源，保留同一素材的来源信息。图片丢失时保留文字入口，不显示与主题无关的随机替代图片。部署细节见 [部署方法论](../DEPLOYMENT.md)。
